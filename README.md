# CheckStock — Система оперативного учёта складских остатков (ФФ, FBS и FBO)

Веб-прототип на **FastAPI + SQLAlchemy (Async SQLite) + Jinja2** для сквозного учёта остатков товаров на физических складах фулфилмента (`Север`, `Юг`) и каналах продаж маркетплейсов (`Wildberries`, `Ozon`, `Яндекс.Маркет`).

## Ключевые возможности и архитектура

* **Сквозной расчёт остатков (ФФ / FBS / FBO):**
  * **Физические склады (`Север`, `Юг`):** хранят физический остаток (`physical_qty`) и автоматически вычисляют доступный к продаже остаток (`Доступные = Наличие − Резерв FBS`) с привязкой каждого резерва к складу-источнику (`source_ff_id`).
  * **Маркетплейсы (`WB`, `Ozon`, `Яндекс.Маркет`):** раздельный учёт активных резервов **FBS** (`reserved_qty`) и партий в пути **FBO** (`transit_qty`).
* **Управление движениями товаров:**
  * **Приход и возвраты (`/stock/income`):** оприходование от поставщика (включая автоматическое создание новых артикулов `SKU` на лету), возврат из резерва FBS, возврат из транзита FBO обратно на полку ФФ и внутренние перемещения между складами.
  * **Отгрузка и резервирование (`/stock/transfer`):** резервирование под заказы FBS, отгрузка в транзит FBO и межуровневые перемещения с защитой от отрицательных остатков.
* **Асинхронный транзакционный стек:** полностью неблокирующий бэкенд на `FastAPI` + `SQLAlchemy AsyncSession` (`sqlite+aiosqlite:///:memory:`), готовый к переходу на **PostgreSQL** заменой строки подключения `DATABASE_URL`.
* **Защита данных и интерфейс:** валидация количества (`quantity > 0`), нормализация артикулов, безопасное экранирование уведомлений и таблица с фиксированной шапкой (`position: sticky`).

## Стек технологий

* **Тестирование:** Pytest (`pytest-asyncio`)

## Локальный запуск

1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

2. Запустите сервер (на свободном порту `5050` во избежание конфликтов с зарезервированными портами Windows):
   ```bash
   python main.py
   ```
   *(Либо через Uvicorn: `python -m uvicorn main:app --host 127.0.0.1 --port 5050`)*

3. Откройте в браузере:
   `http://127.0.0.1:5050`


## Запуск автотестов

```bash
python -m pytest -v
```

## Руководство о работе программы и логике действий

Система **CheckStock** предназначена для сквозного учёта товарных остатков между базовыми фулфилмент-складами (**Север**, **Юг**) и каналами продаж на маркетплейсах (**Wildberries**, **Ozon**, **Яндекс.Маркет**) по схемам **FBO** и **FBS**.

Вся работа ведётся с единой лицевой панели (`http://127.0.0.1:5051`), где в реальном времени отображаются таблицы остатков и две операционные формы.

---

### 1. Логика учёта остатков по складам и каналам

Каждый товар в базе привязан к конкретному складу и учитывается по четырём показателям:

* **Физический остаток (`physical_qty`)** — фактическое количество единиц товара, физически лежащее на базовом складе (**Север** или **Юг**).
* **Резерв FBS (`reserved_qty`)** — количество товара, забронированное под заказы маркетплейсов по схеме **FBS**. Товар остаётся на базовом складе до момента отгрузки покупателю, но уже недоступен для других операций.
* **В пути / FBO (`transit_qty`)** — количество товара, отправленное на склады маркетплейсов по схеме **FBO** (сразу списывается с физического остатка базового склада).
* **Доступно (`available_qty`)** — свободный остаток на базовом складе, доступный к новой отгрузке или перемещению. Рассчитывается автоматически по формуле:
  $$\text{Доступно} = \max(0,\ \text{Физический остаток} - \sum \text{Резерв FBS})$$

---

### 2. Логика действий на лицевой панели

#### Действие 1. Оформить приход, внутреннее перемещение или возврат (`/stock/income`)
Форма отвечает за пополнение базовых складов (`Север` или `Юг`) и имеет три режима в зависимости
от выбранного источника:
1. **Приход от поставщика (`Поставщик / Новое оприходование`):**
     * Увеличивает **Физический остаток** выбранного базового склада.
     * Работает **двухсторонний контроль «1 товар = 1 артикул»**:
     * При вводе существующего артикула (например, `SKU-101` или `101`) 
     * поле **«Наименование товара»** автоматически заполняется эталонным 
     * названием из базы (`Водка`) и блокируется от случайного изменения.
     * На сервере дополнительно блокируется попытка завести новый артикул 
     * с уже занятым наименованием либо изменить наименование у существующего артикула.
     * Для нового артикула система требует обязательного ввода уникального наименования товара.
2. **Внутреннее перемещение между базовыми складами (`Север ↔ Юг`):**
   * Проверяет наличие достаточного остатка на складе-источнике.
   * Списывает количество со склада-отправителя и зачисляет на склад-получатель
   * без дублирования карточек.
3. **Возврат товара с маркетплейса (раздельный учёт `FBO` и `FBS`):**
   * В списке источников каждый маркетплейс разделён на два независимых 
   * канала: `WB (FBO)` и `WB (FBS)`, `Ozon (FBO)` и `Ozon (FBS)`, `Яндекс.Маркет (FBO)` 
   * и `Яндекс.Маркет (FBS)`.
   * **Возврат с FBO:** уменьшает остаток строго в канале **FBO (`transit_qty`)** и
   * возвращает товар в **Физический остаток** выбранного базового склада.
   * **Возврат с FBS:** снимает бронь строго из **Резерва FBS (`reserved_qty`)**
   * (тем самым увеличивая графу **Доступно** на базовом складе), не затрагивая 
   * остатки FBO и не искажая физический остаток.

#### Действие 2. Отгрузка и распределение на маркетплейсы (`/stock/transfer`)
   Форма управляет списанием и резервированием товара с базового склада (`Север` или `Юг`)
   на витрины маркетплейсов:
1. **Перед любой операцией система проверяет реальный **Доступный 
   * остаток** (`Физический остаток − Резерв FBS`). Если свободного 
   * товара меньше запрошенного количества, операция отклоняется с 
   * указанием точного доступного остатка.
2. **Отгрузка по схеме FBO (`WB`, `Ozon`, `Яндекс.Маркет`):**
   * Списывает товар с **Физического остатка** базового склада.
   * Зачисляет указанное количество в графу **В пути / FBO (`transit_qty`)**
   * выбранного маркетплейса с привязкой к складу-отправителю (`source_ff_id`).
3. **Бронирование по схеме FBS (`WB (FBS)`, `Ozon (FBS)`, `Яндекс.Маркет (FBS)`):**
   * Фиксирует количество в графе **Резерв FBS (`reserved_qty`)** выбранного маркетплейса.
   * Физический остаток на базовом складе сохраняется, но показатель **Доступно** мгновенно 
   * уменьшается на величину резерва.
---
### 3. Гарантии целостности данных («защита от ошибок»)
* **Запрет отрицательных остатков:** ни одна операция прихода, возврата или отгрузки не
*   может увести физический остаток, резерв или транзит ниже нуля.
* **Транзакционность:** все изменения фиксируются атомарно (`commit` только 
*   после успешного прохождения всех проверок валидации).
* **Единый справочник номенклатуры:** исключено задвоение 
*   артикулов с разными названиями или одинаковых названий 
*   под разными артикулами как на уровне интерфейса, так и на уровне бэкенда.
